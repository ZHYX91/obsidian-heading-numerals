# 产品需求

[English synced translation](product-requirements.en.md)

<!-- section: authority -->
## 文档权威性

本文是 Document Numbering 产品需求的中文规范源。英文文件是同步译本。实现、测试或旧文档与
本文冲突时，应先更新中文规范源、评审差异，再同步英文；历史验收记录只能证明对应候选与
宿主环境，不能修改产品要求。

<!-- section: purpose -->
## 产品目的

Document Numbering 让用户分别控制“标题序号是否写入 Markdown”和“标题序号是否在 Obsidian
中可见”。插件必须允许用户保持纯净源文件、保存实体序号、隐藏实体序号或以计算序号替换其
视觉呈现，同时保持所有文件修改可预览、可解释并尽量可恢复。

<!-- section: users-and-jobs -->
## 用户与核心任务

- 只想在 Obsidian 中看到层级序号、但不想污染 Markdown 的用户。
- 需要向其他工具输出带实体序号 Markdown 的用户。
- 已有实体序号，希望临时隐藏或安全清理的用户。
- 需要公文、法律条文或自定义层级格式的用户。
- 需要对当前笔记、文件夹或整个库执行一致操作的用户。

<!-- section: scope -->
## 范围

产品处理顶层 ATX H1-H6 标题，支持实时预览、阅读视图、当前笔记写入操作、批处理、内置及
自定义方案、精确标题排除、按笔记 Properties 覆盖、纯显示题注编号、同文件语义交叉引用和
中英文界面。标题方案、每种题注计数和引用解析都以单个 Markdown 文件为作用域；嵌入文件仍
按自己的源码与设置处理。

<!-- section: functional-requirements -->
## 功能要求

1. 虚拟显示和视觉隐藏不得修改 Markdown。
2. 写入、清理、重新编号和移除来源标记必须先生成不可变预览计划。
3. 虚拟显示、阅读视图和文件修改必须共享同一编号语义。
4. 空 Hn 模板不输出序号，但仍增加计数、重置后代并参与后代模板。
5. 非空 Hn 模板必须包含本层占位符，且不能引用后代层级。
6. 旧最大编号层级设置在迁移完成前必须由可回滚兼容层保持现有效果。
7. 自定义方案修改或删除前的模板必须可用于识别历史插件序号，直至用户明确清除历史。
8. 精确排除不得使用模糊或正则匹配；排除标题不得占用计数。
9. 未触碰的笔记不得被写入插件 Properties；恢复继承必须删除相应属性。
10. 只有顶层 `Figure:`、`Table:`、`Equation:` 和 `Code:` 段落声明题注；不兼容
    `Listing:`。四种类型在每个 Markdown 文件内分别从 1 开始，无论是否存在块 ID 都编号，
    显示路径不得写入实体题注编号。
11. 只有 `@[[#标题]]` 和 `@[[#^块ID]]` 及其可选 Obsidian 别名请求同文件语义增强；普通
    链接保持原样。解析只消费已有锚点，且仅在唯一目标具有可见有效标题或题注编号时增强。
12. 插件不得创建、校验、迁移、修复或以其他方式管理标题 ID 或块 ID。

<!-- section: safety-requirements -->
## 安全要求

- 对小数、版本、年份、日期和单位数量等歧义前缀默认失败关闭。
- 写入不得静默覆盖未确认的人工序号。
- 当前笔记确认前必须复核文件、视图和预览源内容。
- 批处理必须复核全部目标内容、保存有界恢复数据，并在并发冲突时停止而不是覆盖。
- 来源标记必须默认关闭，并提供保留可见序号的移除路径。
- 插件不得包含联网、遥测、广告或远程资源。
- 实体标题变化可能破坏标题链接；插件必须提示风险，不得猜测重写链接。

<!-- section: non-goals -->
## 非目标

- 不支持正文内局部方案切换，也不支持已冻结题注和显式语义引用声明之外的用户自定义控制语法。
- 不自动重写标题链接、嵌入或外部锚点。
- 不解析跨文件语义引用。
- 不承诺 Setext、Canvas、Outline、Backlinks、Search Results 或 PDF 导出集成。
- 不把自动测试、模拟器记录或构建成功表述为所有宿主平台验收。

<!-- section: acceptance -->
## 产品验收

每项需求必须有纯逻辑或适配层测试；涉及真实 Obsidian UI、IME、移动端、主题或生命周期的
声明还必须有隔离 Vault 中的带日期记录。源码检查、候选包检查、宿主验收、实体设备验收和
公开发布状态必须分别报告。详细规则见[测试策略](testing-strategy.zh-CN.md)和
[发布策略](release.zh-CN.md)。
