- Obsidian recognized and enabled Heading Numerals 0.4.1. Live Preview and Reading View rendered
  virtual numbering while concealment was also enabled, and a fenced-code heading stayed raw.
- Real Gboard Pinyin produced visible `ce shi` preedit and the `测试` candidate. Preedit preserved the
  fixture's SHA-256 `38939f70d1d154e527626931e555df0e0f13cf4c6d57f91f7f0fb0952de81e5e`;
  committing the candidate changed the source, and mobile undo restored the exact original hash.
- The command palette exposed all ten Heading Numerals commands. Write preview reported four changes
  and one warning, preserved the unmarked `3.14`-looking heading, and applying it produced SHA-256
  `45ae2dae7b4d221e944968c5b4f3fcefe38e7a1d930fa8b9e08c94942b325ec5`.
- Explicit template cleanup previewed five changes and zero warnings, including the unmarked `3.14`

  `ad1a91829db852fb5e6ab7ea09519e9043c4c36bec88e1c73824ffb7f82c5a43`.
  One undo restored the written hash; a second undo restored the exact original hash. Thus automatic
  writing failed closed on the ambiguous prefix, while destructive template cleanup remained an
  explicit, previewed user action.
- A cold application restart reopened the note with virtual numbering and concealment active, while
  the file still matched its original hash. Logcat contained no plugin fatal exception, uncaught
  exception, `TypeError`, or `ReferenceError` from the run.

## Method and cleanup

Interaction used visible emulator screenshots, ADB input, the Android accessibility hierarchy,
package state, file hashing, and logcat. The Chinese case used Gboard's real composition pipeline,
not injected final Chinese text. After acceptance, the emulator loaded the pre-existing
`clean_zh_gboard` snapshot; the acceptance Vault was no longer present and the snapshot remained the
only saved AVD snapshot.

## Explicitly open

- This is emulator evidence, not physical Android-device or iOS acceptance.
- Rotation, background memory pressure, vendor keyboards other than Gboard, hardware keyboards, and
  third-party mobile themes remain open.
- U+2060 source markers remain experimental and disabled by default; no marker-enabled release claim
  is made.
- Folder/Vault batch mutation and recovery were not run on Android.
- No candidate asset was deployed to the formal Vault during this acceptance pass.
